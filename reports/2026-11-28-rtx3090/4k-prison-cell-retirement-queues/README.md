# Prison-cell result with sharded resource retirement

The 4K run with thread-sharded retirement queues presented **1,193 frames in two minutes (9.94 FPS)** in the cell. The slowest five seconds averaged 1.8 FPS, the 95th-percentile frame took 164 ms, and one frame took 3.525 seconds. The median draw count was 6,569. Physical memory available to Windows stayed at or above 4.24 GiB. The player subsequently reached the A-102 officer and dayroom. The driver missed the gate start and closed the game normally after its visual checks. There is no two-minute escort result for this run. [Scene sequence](locations.jpg) · [Frames](cell-frames.csv) · [Metrics](cell-metrics.json)

The 3.525-second frame contained three overlapping 64 KiB reads from the file-backed guest-memory pool. Their union spanned 3.421 seconds. Windows reported zero new process hard faults over 3.000 seconds of samples inside this frame. Another 3.370-second frame had overlapping reads covering 3.262 seconds. In total eleven file-backed copies lasting over 100 ms were observed in the cell interval. The regular direct-copy path was used; the individual source and destination waits remain unresolved. [Overlap and sampling coverage](mapped-read-frames.csv) · [Copy timings](slow-buffers.csv)

The CPU-only queue fixture had previously shown shorter waits with eight producer threads. This run has a different viewpoint and draw count from the prior cell runs and does not establish a game speedup. It used the original 160 × 90 indirect-light grid, 0.05 diffuse floor, Series X profile, 3840 × 2160 output, and no frame generation or DLSS. Ryzen 7 3700X, RTX 3090, 32 GiB system RAM, SSD.
