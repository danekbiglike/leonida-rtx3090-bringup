# Overlapping command recording and descriptor writes on the Ryzen 7 3700X

For large staging batches one worker now records the copy command list while other workers build the independent constant-buffer views. All copy commands and barriers still go into one command list in their original order. Each descriptor slot has one writer, which applies its updates in submission order. Closing and submitting the list happens after the workers finish. This uses the existing worker pool and leaves render resolution, shaders and scene settings alone. [Patch against the batched descriptor build](overlap-list-and-views.patch) · [Previous descriptor change](../d3d12-batched-cbv-slot-readback)

The D3D12 test required two concurrent pool participants to rendezvous before recording a real copy and writing descriptors. After execution on the RTX 3090, the copied word was 101 and shader reads across two descriptor heaps gave 104, 101 and 106. Six additional regression tests passed, including staged reads, writes to repeated slots and isolation across submissions. This establishes the tested ordering and GPU data. Gameplay speed is measured separately. [Hardware checks](hardware-checks.json)

In the [previous 17.95 FPS staging run](../4k-compact-staging-a102-escort), the submission thread spent 39.20 ms of CPU per present. The five existing staging helpers spent 0.63 to 1.03 ms each per present in that walk. The six list-translation threads already ran in parallel and each did 21.6 to 25.7 ms of CPU work per present. These are overlapping thread timings. [Per-thread samples summarized](staging-control-cpu.json)

The candidate samples every 64th large batch with at least one descriptor group. Within a sample it measures the longest intersection between the copy recorder's time and any group's descriptor-writing time. Overlapping samples demonstrate concurrency. The intersection is a wall-time observation, not a direct estimate of net frame-time savings. The script takes a finished trial folder and a destination JSON file. Pass `--cell` for the separately timed cell interval. [Measurement script](measure_preparation.py)
