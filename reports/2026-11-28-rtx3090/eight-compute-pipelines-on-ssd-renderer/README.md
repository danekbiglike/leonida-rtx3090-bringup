# All eight previously omitted compute pipelines created on the RTX 3090

The 4K prison run on the SSD-backed renderer identified eight failing compute shaders. On the same RTX 3090 all eight now translate, pass the Microsoft DXIL validator and create a D3D12 compute pipeline state. The old renderer failed to translate all eight. The earlier standalone PR 994 build passed seven. The CSV lists the input and emitted code hash prefixes and the two checks for each shader. [Per-shader results](coverage.csv) · [Prior three-build comparison](../seven-compute-pipelines/) · [Original corridor trace](../../2026-11-27-rtx3090/stable-player-corridor-boundary-captures/)

The working renderer now binds the descriptor heap's guest-address table at the root slot the translated shader expects. On native D3D12 we use the driver's lane-read operation. For a 64-lane console wave split over two 32-lane host waves, our translator can recognize a uniform-address shared-memory load after a group barrier. The analysis joins branches in both directions and rejects a phase containing a competing write. A barrier that only issues a memory fence cannot establish the read-only phase. These changes build on the heap addressing and partial-wave dispatch work in the upstream projects. [Heap-address changes](https://github.com/fxceless/victory-fork/pull/738) · [NVIDIA partial-wave changes](https://github.com/trustno1-coder/VIctory-NVIDIA/pull/403)

We ran `victory translate --jobs 1 --validate --pipelines --list <private-input-directory>` with `VICTORY_HOST_WAVE=32`, `VICTORY_VIEW_LIMIT=999999`, `VICTORY_BVH_BUILDER=1` and `VICTORY_NATIVE_LANE_READ=1`. We checked that the graphics patch applies to the tree of the previously measured local SSD renderer, `852c9f8c0e8efc67a8bc4887adf913230d3aa6e3`. The patch includes a synthetic barrier test.
