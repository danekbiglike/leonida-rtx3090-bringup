# Seven previously omitted compute shaders pass DXIL validation and pipeline creation

We compared the same eight compute shader containers previously reported as untranslatable in the RTX 3090 prison run. The original SSD build reproduced all eight failures offline. The current fxceless build emitted and validated three. PiloteCode's PR 994 build with paired-wave translation enabled emitted seven, validated all seven with Microsoft's DXIL validator and created seven D3D12 compute pipeline states. Shader dbdbf36298727135 still fails on a cross-lane mask read. [Per-shader results](coverage.csv) · [Original failure set](../../2026-11-27-rtx3090/warm-pipeline-failures/) · [PiloteCode PR 994](https://github.com/fxceless/victory-fork/pull/994) · [fxceless revision](https://github.com/fxceless/victory-fork/commit/2eade68cade9b2f8cd2511cc97328e83f58508c3)

All runs used the 32-lane host setting, the 999999 null descriptor slot, and one translation worker. The PR 994 binary was built from 0021257924461d967266cc6b0974ab724903fb5a with local game-data mounting, input, SSD physical-pool and frame logging changes. Its SHA-256 was 9309e23b38adb31384ac75ccafce50614ad44c36493ea2b390ba57732d97a87d. Settings for the PSO test included VICTORY_WAVE_PAIRS=1 and VICTORY_BVH_BUILDER=1. The command was `victory translate --jobs 1 --validate --pipelines --list <local-corpus>`. The preliminary baseline and fxceless runs used the same command without `--pipelines`. The comparison covers these eight containers only.

PSO creation establishes that the driver accepts the pipeline. Shader outputs, the appearance of skin and lighting, and a gameplay FPS gain still need a scene comparison. A separate interactive test of the PR 994 build exited during the cold load at the same guest offset as the latest fxceless build. Its minimum available physical RAM was 11.23 GiB. The job peaked at 19.67 GiB against a 41.96 GiB limit. The game and its shader containers remain local.
