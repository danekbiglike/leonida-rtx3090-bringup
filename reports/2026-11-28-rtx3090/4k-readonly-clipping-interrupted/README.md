# Interrupted RTX 3090 run with read-only clipping enabled

The control and this run used the **same renderer executable**, the same 4K settings and the same 14 GiB working-set ceiling. In the control the renderer kept shader write declarations and audited compare results. In this run it enabled clipping instead. Of 133 telemetry samples, 83 recorded clipping and the highest reported 361 MB per frame. The renderer logged an unhandled application exception and exited with code `0xc0000005`. Only one present landed after the cell start marker. The trial produced no complete cell or gate FPS score. One interrupted run cannot establish what caused the exception. [Control](../4k-prison-depth-and-write-audit) · [Trial outcome](outcome.json)

The final interval between presents lasted **55.833404 seconds**. The renderer timed **55.628240 seconds** inside a single 64 KiB copy from a mapped view. Looking up the view and obtaining its window each took less than one measured microsecond. Windows sampled that worker 72 times during the copy and reported `Wait / Executive` each time. Free physical RAM stayed above 5.13 GiB during the final frame. The exception appeared in the log between the two presents. These wall-clock timings include waiting and any effects of exception handling, so they cannot establish normal copy speed, which page was responsible, or a specific lock.
