# Batch CPU descriptor updates on the 4K staging control

The renderer previously acquired the shader-heap registry's read lock for every updated constant-buffer slot. This candidate acquires it once per nonempty worker batch and remembers the last resolved heap inside that batch. The GPU address of the shared staging buffer is already available before dispatching the workers. The batch reuses it when building raw views. Existing single-slot callers still query the address only if they need a raw view. This ports the descriptor part of [mikael-jarvinen's PR 1157](https://github.com/trustno1-coder/VIctory-NVIDIA/pull/1157) onto our [zero-gap staging control](../4k-compact-staging-a102-escort). [Local patch](batched-slot-writes.patch)

The existing worker partitions still hold references to the scheduled operations, and each slot stays in its original worker in submission order. A new D3D12 test exercises repeated slots, switches between two live descriptor heaps, and includes a missing heap. A compute shader reads the updated CBVs back on the RTX 3090. All three values matched the final write for their slot: 104, 101, and 106. Separate tests verified compact, joined and capacity-fallback copies and isolation of data between submissions. This test verifies the CBV path. It does not independently sample the raw-view twin. [Test output](hardware-checks.json)

The tests establish GPU data correctness for those cases. Gameplay FPS requires a separately timed walk. The patch is relative to our local staging build, including its existing worker partitioning, and retains VIctory's original license.
